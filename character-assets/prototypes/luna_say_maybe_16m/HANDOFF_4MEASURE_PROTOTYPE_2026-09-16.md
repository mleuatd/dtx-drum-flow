## 現在の手足解析

1〜4小節で必要な動作キーは以下の5種類。

1. SN:L
2. SN:R
3. HH:R
4. BD:RF
5. BD+RC:*

1〜4小節は 28ノーツ / 27 time-group。
手足順序は事前解析済みで、描画時に単純なパート固定推測へ戻さない。

特に1小節目:
- 4.714583 SN = L
- 4.930410 SN = R
- 5.038324 SN = L
- 5.146237 RC = R + BD = RF

この R→L→Crash:R の流れを崩さない。

## 見た目の絶対ルール

人物の絵柄は既にユーザー承認済み。今後勝手にデザインを変えない。

- 白黒
- とてもラフで、線がぐしゃぐしゃした手描き感
- 綺麗・滑らか・整った線へ寄せない
- 長髪
- 頭頂部の癖毛は「なし」で確定
- チェック柄の長袖トップ
- プリーツスカート
- 靴下
- ごつめの編み上げ靴
- 椅子は人物側に含める
- 左向き寄りの横〜後方3/4構図
- 人物の顔・髪・服・椅子・靴・体型・線の荒さ・基本構図を勝手に変更しない
- 差分では必要な腕・手・足・必要最低限の体の傾きだけ変更
- 腕の振り方は実際にドラマーとして自然な可動域にする
- ドラムセットは人物画像へ焼き込まない
- 人物差分は透過レイヤーとして扱う
- 叩いた瞬間の簡単な発音エフェクトを人物側/最前面に含めてもよいが、ドラム本体は描かない

## パラパラ漫画の動き方

ユーザーが欲しいのは滑らかな中割りアニメではない。

基本:
1. 初期/neutralポーズ
2. ノーツの瞬間にそのノーツ用の人物差分
3. 次の高速連打がなければ、短時間で初期/neutralへ戻る

ノーツ間が荒いことを活かして「カクッ、カクッ」と切り替える。
差分を大量に増やして滑らかに補間しない。

## 画像作成の進め方

一度に複数の絵を1枚のシートへまとめない。
必ず「1差分 = 1画像」で作る。

1枚作る
→ ユーザーがOK
→ GitHubへバイナリcommit
→ 次の1枚

を繰り返す。

## 1〜4小節の完成フロー

### フェーズA: 差分画像を揃える

不足している差分を1枚ずつ作成する。
差分3枚目 → 確認/承認 → commit
差分4枚目 → 確認/承認 → commit
差分5枚目 → 確認/承認 → commit

必要5キーすべてについて、どの画像がどのキーに対応するかGitHub上のmanifest/inventoryへ記録する。

### フェーズB: 4小節プロトタイプへ実装

必要画像が揃ったら、1〜4小節について実際のノーツ背景/人物レイヤーへ差し込む。

- 固定ドラムレイヤー
- 人物差分レイヤー
- 必要なら発音エフェクト最前面
- ノーツ/レーン表示

を重ねる。

`site/character-prototype.js` は事前解析済みの limb を最優先する。
1〜4小節では正しい差分画像を使用し、誤った手の画像をfallbackとして使わない。

### フェーズC: 実再生QA

1〜4小節を実際に再生し、以下を確認。

- 手足が解析データ通り
- 左右の手が入れ替わっていない
- 1小節目の SN L→R→L → RC:R が自然
- BDはRF
- BD+RC同時打ちが自然
- ノーツ後に初期ポーズへカクッと戻る
- ドラム位置が一切動かない
- 人物の位置がドラムと合っている
- 椅子が差分ごとに不自然に飛ばない
- 人物とドラムの前後関係が破綻しない
- 不要な滑らか補間をしていない

### フェーズD: 公開確認

4小節プロトタイプをGitHub Pages等の既存公開先へ反映し、ユーザーがリンクを開くだけで確認できる状態にする。

4小節分がOKになったら、そこで作り方を「確立済み」とみなし、5小節目以降も同じ方式で順次拡張する。

## 5小節目以降

4小節プロトタイプの承認後は、毎回方式を作り直さない。

- 譜面から必要差分を洗い出す
- 既存差分で足りるものは再利用
- 新規差分が必要なら1枚ずつ作る
- 承認画像は即commit
- 実装
- 再生QA
- commit / push
- 状態をGitHub文書へ記録

を繰り返す。

## Work / 通常チャットの使い分け

重い作業（多数ファイル調査、まとめて実装、テスト、公開QAなど）は Work を使ってよい。
ただし Work の上限があるため、通常チャットで十分実行できる処理は通常チャットで進める。

Work側で作業したら必ずGitHubへ結果を残し、通常チャットへ戻った時にGitHubだけ読めば続行できる状態にする。
通常チャット側で作業した場合も同様。

会話履歴だけを作業状態の正本にしない。

## 重要

ユーザーへの同じ確認を繰り返さない。
画像生成時に勝手にドラムを描かない。
複数差分の一覧シートを生成しない。
未承認画像を完成品として登録しない。
